# Backbone v0.4.0 — DST-SGNN eigendecomposition stability hotfix

The first DST-SGNN screening run failed inside the pinned official SGSC/LDGOSM path at `torch.linalg.eigh(X_T_X)` after more than 1,400 batches. The Gram matrix is theoretically symmetric PSD, but a rare float32/V100 batch became ill-conditioned enough for cuSOLVER to fail to converge.

## Fix

The official vendor source remains unchanged and source-locked. Only the DST-SGNN adapter temporarily wraps `torch.linalg.eigh` during DST-SGNN forward calls:

- symmetrize the Gram matrix;
- add a relative diagonal ridge of `1e-6`;
- if cuSOLVER still fails, retry with `1e-4` ridge in float64 and cast the eigenpairs back to the model dtype.

Adapter revision:

`dstsgnn_official_h12_patch12_eigh_stable_v2`

## Validation

```bash
python scripts/smoke_dstsgnn_eigh_hotfix.py
qsub -v MODEL=DST-SGNN pbs/recent_adapter_smoke.pbs
```

After the GPU smoke passes, rerun only DST-SGNN screening. PatchSTG and all four Stage-1A results remain valid.
