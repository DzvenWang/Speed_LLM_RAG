# CoRSTA v0.1.0

**Counterfactual Retrieval-guided Spatio-Temporal Adaptation**  
基于预训练 STLAformer，在 TraffiDent 不完整交通观测上联合训练反事实支持学习 C1、可靠性条件时空传播 C2、时间桥接与共享 STLA 末层细化。

> **状态**：v0.1.0 CPU/GPU PBS Preflight hotfix2；完整可运行源代码与 PBS 提交入口；CPU synthetic 全流水线已验证。真实 Gadi/官方 STLA vendor/Checkpoint 需要在用户环境运行 `preflight` 和 GPU profiling；压缩包不包含用户原有大型数据、Backbone vendor、预训练权重或历史实验日志。此版本尚无真实数据上的精度提升结论。

## 1. 目录与依赖

把 `CoRSTA/` 直接放在现有 `Speed_LLM_RAG/` 下，与 `Backbone/`、`Base_SupportBench/` 同级。

```text
Speed_LLM_RAG/
  Backbone/                 # existing Backbone, including vendor/STLAformer
  Base_SupportBench/        # existing shared data / protocol
  Backbone_exps/            # existing STLA best.pt, target-specific
  CoRSTA/                   # this entire delivered directory
  CoRSTA_exps/              # automatically generated
  CoRSTA_logs/              # automatically generated by PBS
```

使用现有 TFP Python 环境，并安装 `CoRSTA/requirements.txt`（使用该环境适配 CUDA 的 PyTorch 版本）。依赖原始 Backbone checkpoint 严格匹配 `target`、`dataset` 和节点数。**不需要** TCRR-STLA 作为运行时包：旧 v7.0.1 的必要代码已独立移入 `CoRSTA/corsta/v7/`，避免新的项目依赖旧顶层目录。

## 2. 架构

- `corsta/student.py`：STLA prefix（前 4 层，默认）→ original tail（后 2 层）→ `P0`；保持原始 `bx` 残差与位置编码的计算位置。
- `corsta/v7/`：固定 TRAIN Teacher、TRAIN-only functional/directional graph、Normal/CF Replay、可靠候选选择、效用监督，**不**从 TEST 未来构建训练记忆。
- `corsta/deep.py/C1SupportTokens`：重用原有 C1 候选权重，将 Normal/CF response 转成分离的支持特征，并输出 None/Compatibility 可靠性。
- `corsta/deep.py/C2ReliabilityGraph`：预测步相关的 Query/Key/**Value**，同时使用历史观测覆盖率和 C1 支持可靠性，融合 functional/upstream/downstream 邻居消息。
- `corsta/deep.py/TemporalBridge`：每节点的 `[B,P,N,d]` 未来支持 → `[B,L,N,D]` 历史 STLA 表示 Cross-Attention。
- `ReliabilityFusion`：独立、保守的 C1/C2 门控，之后与第一次 forward 共享相同 STLA Tail 参数，输出 `refined`。
- `corsta/training.py`：Warm-up、Partial Joint Fine-tuning、Selection、Locked Check、s20/s40/s60/s90 TEST 和 checkpoint/resume。

默认不启用直接最终残差头（`direct_residual_head: false`）。`c1_posthoc` 仅作为并列诊断预测输出；正式 `refined` 经过 STLA 特征细化生成。该配置字段目前只接受 `false`，不是一个已实现的可切换残差融合机制。

**冻结 Teacher 与在线 Student 分离**：历史 Normal/CF 仍由固定 Teacher Cache 产生，实时查询预测与隐藏态来自可训练 Student；模型的 `forward` 不读取 query 真实未来。检索 Top-K 仍为非可微分的固定 TRAIN-only 召回，C1 candidate weighting、C1/C2/Bridge/Student 的内部 Forward 可微。

## 3. 日志格式

所有 Python stdout/stderr 行（包括 traceback/warnings）被 `install_timestamps()` 前缀为 UTC ISO-8601：

```text
[2026-11-02T12:00:01Z] CORSTA_STAGE_START stage=joint
[2026-11-02T12:00:02Z] CORSTA_BATCH_PROBE size=64 success=True peak_gib=... reason=pass
[2026-11-02T12:00:03Z] CORSTA_BATCH_SELECTED batch=64 initial=64 alternatives=(16, 32, 64, 128)
[2026-11-02T12:00:04Z] CORSTA_EPOCH phase=joint epoch=1/20 ... selection_mae=... throughput=... gpu_peak_gib=...
```

以上仅是格式示例，数值与时间戳不是正式实测。PBS 通过幂等 `timestamp_filter.py` 避免双重时间戳，`tee` 保存 `.live.log`；PBS 自身 PASS/FAILED 行也有 UTC 时间。`--stage` 进程中的 legacy bootstrap 日志同样逐行有时间戳。

## 4. 自动 Batch Size（16 / 32 / 64 / 128）

默认 `batch_mode: auto`、**初始 Batch Size=64**：

1. 在当前训练阶段，以真实样本形状、真实 CoRSTA 模型，执行 **Forward + Backward**，测 CUDA peak allocated memory。
2. 64 通过且预留充裕时，**仅尝试 128**；如果 128 失败，保持 64。
3. 64 失败时，严格按 **32 → 16** 降级，不浪费显存测试更大的 128。
4. Probe 留出较大的显存安全余量（默认目标不超过总显存的 85%，并有额外 buffer）。Stage 内意外 OOM 则回退一个级别，从**上一个完整 Epoch checkpoint**回滚模型、优化器、Scaler 和随机状态，再重做整个 Epoch。
5. 每阶段记录 `batch_probe_warmup.json`、`batch_probe_joint.json`、`CORSTA_BATCH_PROBE`、`CORSTA_BATCH_SELECTED` 和 `CORSTA_RUNTIME_OOM`。Bootstrap 的 S0/Normal/C1 阶段也会在 CUDA 上做各自阶段的自动 batch probe。自动选择不修改 replay 数据或数据拆分。

若连 Batch 16 也不能运行则明确失败，不伪装成成功，也不会隐式退回 CPU。

**注意**：Probe 是保守的初始显存估算，不能代替真实 V100 完整训练 profiling；DataLoader、优化器状态、CUDA 碎片化均可能造成真实耗用略高。CPU smoke 不检测 GPU 显存，使用简化 Batch=16。

可以在 `configs/corsta_v0_1.yaml` 或 CLI 中设置 `--batch-initial 64` / `--batch-mode auto`（支持 16、32、64、128）。`effective_batch: 64` 用梯度累计维持最低约 64 的名义有效 Batch。单卡 32GB V100 不保证 128 一定可用。

## 5. Gadi Preflight：实际使用 CPU PBS，GPU PBS 保留为可选

CoRSTA 正式训练依然必须有 CUDA GPU，但 **Preflight 只需要 CPU**。
Preflight 包括：真实 STLA Checkpoint 检查、官方 Vendor 导入、原 STLA 与拆分后 STLA FP32 Forward 等价性检查；并不包括 GPU 峰值显存探测或 CoRSTA 全量训练。
CPU/GPU 两种 PBS Preflight 均不会写入正式训练的 `CoRSTA_exps/.../run_identity.json`，所以可先完成检查再独立提交正式训练。

Gadi 登录节点设置（与你目前的环境变量一致）：

```bash
cd /scratch/mh20/zw1165/Speed_LLM_RAG
conda activate TFP
export SPEED_LLM_RAG_ROOT="$PWD"
export TARGET=speed
export DATASET=TraffiDent_Net_06
export SEED=10
export BACKBONE_MODE=incomplete
export BACKBONE_CHECKPOINT="$PWD/Backbone_exps/speed/STLAformer/TraffiDent_Net_06/formal/20260930_215233_seed10/best.pt"
```

**推荐实际执行：CPU PBS（不申请 GPU）**

```bash
qsub -N CoRSTA_pre_cpu \
  -v TARGET="$TARGET",DATASET="$DATASET",SEED="$SEED",BACKBONE_CHECKPOINT="$BACKBONE_CHECKPOINT",BACKBONE_MODE="$BACKBONE_MODE" \
  CoRSTA/pbs/preflight_cpu.pbs
```

此脚本使用 `normal` 队列，申请 `ncpus=4,mem=16GB,walltime=00:30:00`。
成功标志：`CORSTA_PREFLIGHT_PASS` 和 `CORSTA_PREFLIGHT_PBS_PASS mode=cpu`；输出写入 `CoRSTA_logs/preflight/<target>/<mode>/`，且每一行均有 UTC 时间戳。

**保留的可选执行：GPU PBS**

```bash
qsub -N CoRSTA_pre_gpu \
  -v TARGET="$TARGET",DATASET="$DATASET",SEED="$SEED",BACKBONE_CHECKPOINT="$BACKBONE_CHECKPOINT",BACKBONE_MODE="$BACKBONE_MODE" \
  CoRSTA/pbs/preflight_gpu.pbs
```

GPU Preflight 明确使用 `--require-cuda`：没有 CUDA 会直接失败，绝不静默降级为 CPU。
原 `CoRSTA/pbs/train.pbs` 仍支持 `CORSTA_STAGE=preflight` 的 GPU 提交方式，并自动添加 CUDA 要求；`CORSTA_STAGE=all` 等正式训练保持 GPU PBS。

**正式训练**（Preflight PASS 后执行）：

```bash
qsub -N CoRSTA_speed \
  -v TARGET="$TARGET",DATASET="$DATASET",SEED="$SEED",BACKBONE_CHECKPOINT="$BACKBONE_CHECKPOINT",BACKBONE_MODE="$BACKBONE_MODE",CORSTA_STAGE=all,BATCH_INITIAL=64 \
  CoRSTA/pbs/train.pbs
```

**CPU PBS 只检查模型结构，不会运行自动 Batch Size 探测。** 正式 GPU 训练仍从 64 开始，依次测试 128 或回退 32/16。

### 5.1 补充：原有 Gadi 训练入口（兼容）

```bash
cd /scratch/mh20/zw1165/Speed_LLM_RAG
conda activate TFP
export SPEED_LLM_RAG_ROOT="$PWD"
export PYTHONPATH="$PWD/CoRSTA:$PWD/Backbone:$PWD/Base_SupportBench:${PYTHONPATH:-}"
export BACKBONE_MODE=incomplete
export TARGET=speed
export DATASET=TraffiDent_Net_06
export SEED=10
export BACKBONE_CHECKPOINT="$PWD/Backbone_exps/speed/STLAformer/TraffiDent_Net_06/formal/20260930_215233_seed10/best.pt"
```

上面的 checkpoint 路径是之前 STLA speed 实验的一条示例路径；以实际存在且匹配 target/dataset 的路径为准。

如需在已分配的 CPU 计算节点手动检查，命令是：

```bash
python -u CoRSTA/scripts/run.py \
  --stage preflight --target "$TARGET" --dataset "$DATASET" \
  --seed "$SEED" --backbone-checkpoint "$BACKBONE_CHECKPOINT" --cpu
```

Preflight 成功后再提交完整流水线。正式训练仍必须在 GPU 计算节点执行；该热修复还会在**仅存在旧 preflight 空壳、未开始任何训练**时安全刷新旧代码哈希的 run identity，已产生训练数据或 checkpoint 的运行不会被自动覆盖。

然后提交完整流水线：

```bash
export CORSTA_STAGE=all
export BATCH_INITIAL=64
qsub -N CoRSTA_speed \
  -v TARGET="$TARGET",BACKBONE_CHECKPOINT="$BACKBONE_CHECKPOINT",DATASET="$DATASET",SEED="$SEED",CORSTA_STAGE=all,BATCH_INITIAL=64,BACKBONE_MODE=incomplete \
  CoRSTA/pbs/train.pbs
```

或者使用同等环境变量执行 `bash CoRSTA/pbs/submit.sh`。如果某个 GPU Job 达到 walltime，重新提交**完全相同**的环境参数和源码版本，自动跳过已完成阶段，并从最近完整 Epoch 恢复。

可手动分阶段提交 `CORSTA_STAGE=bootstrap`、`warmup`、`joint`、`lock`、`test`、`report`。正式的 `test` 必须先锁定模型，不能跳过 Locked Check。自定义 `--run-dir` 应保持不变。模型与 Run Identity 和数据缓存绑定，换配置/代码应使用新 Run Dir。

Flow 单独训练：

```bash
export TARGET=flow
```
