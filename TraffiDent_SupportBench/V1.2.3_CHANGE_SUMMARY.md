# TraffiDent-SupportBench v1.2.3 Change Summary

## Purpose

v1.2.3 fixes the predictive-context metric semantic mismatch identified by the
predictive structured-mask audit. The canonical benchmark structure is not
redesigned.

Formal Chapter-3 metric:

```text
C_q^loss = network_mean_context_loss = mean(per_target_context_loss)
```

Legacy v1.2.2 diagnostic:

```text
aggregate_context_loss = context_loss_quantile_value  # q=0.75 by default
```

The legacy field is retained for backward compatibility but is no longer used
as the formal `predictive_context_loss` in derived experimental artifacts.

## Core code changes

### `supportbench/dependency.py`
- Added `summarize_dependency_context_loss()`.
- Separates formal network mean from legacy target quantile.

### `supportbench/dataset.py`
`predictive_context_metrics()` now exposes:

```text
per_target_context_loss
network_mean_context_loss       # formal Chapter-3 metric
predictive_context_loss         # formal alias
context_loss_quantile
context_loss_quantile_value     # legacy diagnostic
aggregate_context_loss          # legacy compatibility alias
legacy_aggregate_context_loss
support_dependent_target_mask
support_dependent_fraction
```

### `supportbench/graph.py`
- Corrected predictive-source contribution normalization from non-empty-target
  count to all N targets, exactly matching Chapter-3 `C_q^loss`.
- This is a network-wide scalar rescaling of source contributions; it does not
  change existing greedy predictive layout identities.

## Derived-artifact changes

### `derived/build_support_opportunity_features.py`
- SO-v2 Stage A now uses `network_mean_context_loss`.
- Adds `network_mean_context_loss` and `legacy_context_loss_quantile` to CSV.
- Validation calibrator records the metric semantics.

### `derived/build_support_utility.py`
- Utility NPZ `predictive_context_loss` now means the formal network mean.
- Adds explicit `network_mean_context_loss` and legacy quantile arrays.

### `derived/evaluate_forecast.py`
- Forecast metrics CSV now reports the formal context metric.
- Retains legacy quantile as a separate diagnostic.

### `supportbench/evidence.py`
- Explanation/reasoning evidence now includes the formal predictive-context
  loss explicitly while preserving the legacy aggregate field.

### `derived/build_support_opportunity.py`
- Legacy v1 hand-crafted SO diagnostic uses the formal network mean and writes
  the old quantile separately. Formal experiments should still use SO-v2.

## Audit changes

### `derived/audit_predictive_structured_masks.py`
- Canonical SupportBench API is now authoritative.
- Uses `network_mean_context_loss`, not legacy `aggregate_context_loss`.
- Supports ID and OOD directly from canonical views.
- Existing Stage-A feature CSV is optional and used only as a semantic
  consistency cross-check.
- Reports `PASS`, `WEAK_BELOW_TARGET`, or `REVERSED` rather than treating every
  below-1.05 result as a generic scientific failure.

### `pbs/audit_predictive_structured_masks.pbs`
- Adds `SPLIT` and `BUDGET` explicitly.
- OOD no longer requires OOD rows in `test_support_features_v2.csv`.

## What does not need rebuilding

Do NOT rebuild:
- canonical traffic/core;
- splits/windows;
- existing fixed sensing views;
- Train predictive dependency artifact;
- Train support memory;
- existing Val/Test candidate pools.

## What to rerun on Gadi

First regenerate SO-v2 Stage A using existing candidate pools:

```bash
qsub pbs/build_support_opportunity_features.pbs
```

Then rerun audits:

```bash
qsub pbs/audit_predictive_structured_masks.pbs
qsub -v SPLIT=test pbs/audit_predictive_structured_masks.pbs
qsub -v SPLIT=test,DISTRIBUTION=ood pbs/audit_predictive_structured_masks.pbs
```

After Stage-A/audit consistency is confirmed, freeze the numerical reference
backbone and proceed to support utility/headroom + SO-v2 Stage B.
