# Baseline v0.4.0 — 2026-09-11 hotfix

This hotfix fixes the failures observed in the first Development runs without changing the frozen Shared Protocol, cache identity, official vendor source locks, or evaluation definitions.

## Fixed

1. **GinAR / SARAF result serialization**
   - `view_id` is now written as a native NumPy Unicode array, never `dtype=object`.
   - `allow_pickle=False` remains enforced by the evaluator.
   - Existing completed-but-incomplete GinAR/SARAF runs can be finalized with `scripts/recover_incomplete_result.py` and do not need retraining.

2. **RAFT device mismatch**
   - Precomputed retrieval tensors are moved to the same CUDA device as the official RAFT model before indexed access.

3. **SARAF 5-minute time marks**
   - Numeric row-index columns are rejected as datetime candidates.
   - Genuine timestamp columns must have approximately 5-minute cadence; otherwise a deterministic Monday-based 5-minute axis is used.
   - A time-bonus probe fails loudly if SARAF's time-aware term is constant.

4. **mmap collation warnings**
   - Dataset slices passed to Torch are copied into writable NumPy arrays.

## Recommended recovery

```bash
python scripts/recover_incomplete_result.py --method GinAR --stage development
python scripts/recover_incomplete_result.py --method SARAF --stage development
python scripts/summarize_main_development.py
```

RAFT must be rerun because its first Development run failed before epoch 1.
